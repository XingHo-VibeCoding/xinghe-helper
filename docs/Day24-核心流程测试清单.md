## 阶段 9｜数据一致性（对照数据库）

跑完上面每一轮后，去 CloudBase 控制台 → 数据库 → SQL 编辑器跑这几条，**和页面显示对账**：

```sql
--① 总数对账
select 'rooms' as表名, count(*) from public.rooms
union all select 'students', count(*) from public.students;

-- ② 有没有人挂在不存在的房上（孤儿检查，必须0 行）
select s.id, s.name, s.assigned_room_id
from public.students s
where s.assigned_room_id is not null
  and s.assigned_room_id not in (select id from public.rooms);

-- ③ 分配状态自洽（有房号 ⟺ 已分配，必须 0 行）
select id, name, assigned_room_id, assign_status from public.students
where (assigned_room_id is null) <> (assign_status = '未分配');

-- ④ 重复的 is_latest（同一姓名多条 is_latest=true，必须 0 行）
select name, count(*) from public.students
where is_latest = true group by name having count(*) > 1;
```

**四条都必须是 0 行/对得上**，否则就是真Bug。

## 已知不是 Bug 的现象（别误报）

| 现象 | 解释 |
|---|---|
| 第一次打开弹「页面访问提示」 | CloudBase 对未备案域名的固定拦截，点蓝色「确定访问」 |
| 301 房显示「跨间冲突：女房有打呼噜的，又有睡眠质量差的」 | **分房引擎的正常提醒**，它在提示你这个安排可能影响休息 |
| 页面右下角时间是 UTC 或对不上本地时间 | 之前核对过是正常的，服务器返回带 +08:00 |
| 未分配名单里有「测试同学D20」这类名字 | Day 20 遗留的演示数据，已用 `is_latest=false` 软化过 |
