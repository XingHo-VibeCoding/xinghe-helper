# 同伴交叉验证模板

> 用法：把下面代码块整段发给同伴，让他照着做，**只用手机或自己的电脑打开，不要用你的电脑**。
> 他把三行结论填好发回给你，这三行就是你的第三方证据。

---

## 发给同伴的话

麻烦帮我验证一下这个链接，**用手机或者你自己的电脑打开**，不要在我这台电脑上操作：

```
https://xinghe-helper-d5g92pis442fd9947-1499825718.tcloudbaseapp.com
```

打开后看工作台的房间列表，**随便找一间房（比如 301 或 302），在页面上改一下人数或者性别，然后按 F5 刷新**，看改动还在不在。

弄完把这三行填好发我：

---

```
能否打开：能 / 不能
   （不能的话，把浏览器显示的提示原文抄给我，比如 418、白屏、还是转圈）

能否真实读写：能 / 不能 / 只读
   （改完刷新，改动还在 = 能；改动没了 = 只读；连页面都打不开 = 不能）

有无报错：有 / 没有
   （有的话，请截图，并按 F12 打开控制台，把红色报错那几行抄给我）
```

---

## 填写说明（发给同伴时可以一起给，也可以不给）

- **一定要用手机试一次**，电脑和手机都能开才说明别人真的能用
- 「改完刷新还在」是重点，这是判断有没有真存进数据库的关键
- 如果打不开，先确认地址里有没有 `-1499825718` 这一段，缺了会返回 418
- 报错截图要**包含浏览器地址栏**，这样能看出访问的是哪个地址

---

## 你这边的对账方法（同伴回信后你做）

| 同伴结论 | 说明 | 你的动作 |
|---------|------|---------|
| 三行全绿 | 第三方验证通过，可对外发链接 | 记录到验收表 |
| 「不能打开」 | 多半是漏了 `-1499825718` 后缀 | 让他用完整地址重试 |
| 「只读」 | 浏览器缓存了旧版本，或写接口权限问题 | 让他强制刷新（Ctrl+Shift+R）再试 |
| 「有报错」 | 让他抄控制台红色那几行 | 按报错定位，对照 Day20 文档第 12 节排查 |

**验证成功的标志**：同伴的三行结论和你的 `docs/第3周验收表.md` 里5 项 PASS 对得上，且同伴是在**自己的设备**上测出来的——这比自己本机测更有说服力。
